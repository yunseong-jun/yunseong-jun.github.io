# 전윤성 Jeon Yunseong — Portfolio

경영정보학 전공 전윤성의 연구 포트폴리오입니다.
AI, 데이터, 비즈니스, 인간의 의사결정이 만나는 지점에서 진행하는 연구와 프로젝트, 리더십 활동을 소개합니다.

> 기술을 이해하고, 인간을 탐구하며, 더 나은 의사결정을 설계합니다.

---

## 1. 홈페이지 목적

- **누구를 위한 사이트인가:** 같은 전공 학생과 교수, AI·비즈니스 분야 연구자, 프로젝트 협업에 관심 있는 사람
- **무엇을 전달하는가:** 처음 방문한 사람이 1분 안에 아래 세 가지를 이해하도록 합니다.
  1. 전윤성은 누구인가? → Hero, 소개
  2. 어떤 연구와 프로젝트를 진행하는가? → 연구·프로젝트
  3. 어떤 분야에 관심을 가지고 있는가? → 관심 분야
- **앞으로:** 새로운 연구와 프로젝트를 계속 추가할 수 있는 구조로 만들었습니다.

```
├── #top            Hero — 이름, 전공, 핵심 메시지, 자기소개, Keywords, 버튼 2개
```

## 3. 파일 구조

```
my-homepage/
├── index.html     모든 내용(텍스트)이 들어 있는 파일
├── style.css      디자인. 맨 위 :root 블록에서 색·글꼴·간격을 한곳에서 관리
├── script.js      모바일 메뉴, 현재 섹션 표시, 프로젝트 상세 창, 연락처 복사, 사이트 점검(#qa)
```

빌드 도구, 외부 API 키, 백엔드가 필요 없습니다. 글꼴만 Google Fonts에서 불러오며, 인터넷이 없으면 시스템 글꼴로 대체되어 그대로 작동합니다.

## 4. 실행 방법

**가장 간단한 방법:** `index.html`을 더블클릭해 브라우저에서 엽니다.

**로컬 서버로 열기 (권장 — GitHub Pages와 같은 조건):**

```bash
cd my-homepage
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

VS Code를 쓴다면 Live Server 확장으로 `index.html`을 열어도 됩니다.

## 5. GitHub Pages 배포

1. GitHub에서 새 저장소를 만듭니다. 주소를 `아이디.github.io`로 만들면 `https://아이디.github.io`가 됩니다. 다른 이름(예: `my-homepage`)이면 `https://아이디.github.io/my-homepage/`가 됩니다.
2. 이 폴더의 파일을 저장소 **최상위**에 올립니다. (`index.html`이 저장소 첫 화면에 보여야 합니다.)
   ```bash
   cd my-homepage
   git init
   git add .
   git commit -m "Sprint 1: portfolio homepage"
   git branch -M main
   git remote add origin https://github.com/아이디/저장소이름.git
   git push -u origin main
   ```
3. 저장소의 **Settings → Pages**로 이동합니다.
4. **Build and deployment → Source**를 `Deploy from a branch`로, **Branch**를 `main` / `/ (root)`로 선택하고 Save를 누릅니다.
5. 1~2분 뒤 같은 화면 위쪽에 사이트 주소가 표시됩니다. 수정 후 다시 push하면 자동으로 반영됩니다.

## 6. 수정 가이드 (사용자 테스트 후 고치기)

### 메뉴 문구 바꾸기
`index.html`의 `<nav id="site-nav">` 안 링크 텍스트와, 해당 섹션의 `<h2 class="section-title">`을 **같은 문구로 함께** 바꿉니다.
메뉴를 누른 사람이 같은 이름의 제목을 보고 제대로 도착했다고 확신할 수 있게 하기 위해서입니다. 둘이 다르면 `#qa` 점검에서 '참고'로 알려 줍니다.

### 섹션 순서 바꾸기
`<section id="...">` 덩어리를 통째로 잘라 원하는 위치에 붙이고, 메뉴의 `<li>` 순서도 같이 바꿉니다. CSS·JS는 수정하지 않아도 됩니다.

### 프로젝트 추가하기
1. `article.project-card` 하나를 복사해 붙이고 `id`, 제목, 연구 질문(RQ), 요약, 방법·도구, 키워드, 상태를 바꿉니다.
   카드 안의 **직계 자식 6개**(meta · 제목 · RQ · 요약 · 필드 · 하단)는 지워지지 않게 유지합니다. 카드끼리 줄 높이를 맞추는 데 쓰입니다.
2. 카드 버튼의 `data-open="detail-새이름"`과 같은 `id`를 가진 `<dialog class="project-dialog">`를 하나 더 만듭니다.
3. 진행 단계는 `<span class="stage-meter" data-stage="1">`의 숫자(1~4)만 바꾸면 막대 표시가 바뀝니다.
4. 카드가 4개가 되면 데스크톱에서 3칸 + 1칸이 되므로, 필요하면 `style.css`의 `.project-grid`를 `repeat(2, …)`로 바꿉니다.

### 연락처 채우기
href가 없는 자리는 '추가 예정'으로 흐리게 보입니다. 실제 주소를 넣으면 자동으로 링크와 복사 버튼이 켜집니다.

```html
<!-- 전 -->
<a class="contact-value">이메일 주소 추가 예정</a>
<!-- 후 -->
<a class="contact-value" href="mailto:name@example.com">name@example.com</a>
<a class="contact-value" href="https://github.com/아이디" target="_blank" rel="noopener">github.com/아이디</a>
```

### 프로젝트 A 결과 추가하기
상세 창의 `결과 요약 Findings` 블록에서 `data-placeholder` 속성을 지우고 확인된 결과를 적습니다.

### 색과 글꼴 바꾸기
`style.css` 맨 위 `:root`의 토큰만 바꾸면 전체에 반영됩니다. 다크 모드 값은 바로 아래 두 블록에 있습니다.

### 영어 버전으로 확장하기
1. `index.html`을 복사해 `en/index.html`을 만들고 `<html lang="en">`으로 바꿉니다.
2. 경로를 `../style.css`, `../script.js`로 바꾸고 본문 텍스트만 번역합니다. 구조와 class는 그대로 둡니다.
3. `script.js`의 `UI_TEXT.en`에 버튼·안내 문구가 이미 준비되어 있어, `lang="en"`이면 자동으로 영어 문구가 쓰입니다.
4. 두 페이지 헤더에 `<a href="en/">EN</a>` / `<a href="../">KO</a>` 링크를 추가합니다.

## 7. 수정 후 검증하기

### 자동 점검 (#qa)
주소 끝에 `#qa`를 붙여 엽니다. 예: `http://localhost:8000/#qa`, `https://아이디.github.io/#qa`
오른쪽 아래 패널에 다음 항목의 결과가 나타납니다.

| 점검 항목 | 실패하면 |
| --- | --- |
| 메뉴 링크가 섹션과 연결됨 | 메뉴 `href`와 섹션 `id`의 철자를 맞추세요 |
| 메뉴 문구와 섹션 제목 일치 | 메뉴 텍스트와 h2를 같은 문구로 |
| 페이지 안의 모든 링크가 목적지를 가짐 | `#`로 시작하는 링크의 대상 id 확인 |
| 프로젝트 상세 창 연결 | `data-open` 값과 dialog `id` 확인 |
| 프로젝트 카드 필수 항목 | 카드에서 빠진 제목·RQ·요약·필드·상태·버튼 확인 |
| 중복 id 없음 | 카드나 dialog를 복사한 뒤 id를 바꿨는지 확인 |
| 첫 화면에 방문 대상과 목적 안내 | Hero 패널의 안내 문구 확인 |
| 아직 채우지 않은 자리 | 연락처·결과 요약 등 '추가 예정' 목록 (참고용) |

개발자 도구(F12) 콘솔에서 `siteCheck()`를 실행하면 같은 결과를 표로 볼 수 있습니다.

### 직접 확인 체크리스트
- [ ] 데스크톱: 메뉴 5개를 차례로 눌러 같은 이름의 제목이 화면 위쪽에 보이는지
- [ ] 휴대폰(또는 개발자 도구의 기기 모드, 폭 390px): `메뉴` 버튼으로 열고 닫히는지, 항목을 누르면 메뉴가 닫히고 이동하는지
- [ ] 프로젝트 카드 아무 곳이나 눌러 상세 창이 열리고, `닫기`·Esc·바깥 영역 클릭으로 닫히는지
- [ ] 키보드만으로: Tab으로 `자세히 보기`까지 이동 → Enter로 열기 → Esc로 닫기 → 초점이 원래 버튼으로 돌아오는지
- [ ] 페이지가 좌우로 흔들리거나 가로 스크롤이 생기지 않는지

## 9. 콘텐츠 원칙

- 제공된 사실만 사용했습니다. 기간, 성과 수치, 수상 내역, 논문 실적은 넣지 않았습니다.
